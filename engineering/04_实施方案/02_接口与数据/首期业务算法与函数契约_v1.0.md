## 1. 本次提交的结论与边界

首期可复用的计算基础有三项：0.1.1 简化健康评价、指定故障与给定隔离下的通路分析、少量给定方案的约束检查及固定效用比较。三者可以组成可解释的辅助分析链，但尚不能输出正式 P/C/R/H、失效概率、RUL、压力流量解或正式工程调度结论。

建议审查后冻结以下规则：

1. **Rs/Hs 的权重、分档、有效项重归一、浮点累加顺序、舍入和判级保持原样。** 新解释只增加旁路明细，不改原结果。
2. 原“可信度”准确解释为**有效指标权重占比**。它不是准确率、概率、证据质量或置信区间。缺失项不代表低风险，也不能保证 Hs 只升不降。
3. NetworkX 输出限定为**给定事件及操作假设下的通路影响**。给定阀门关闭不等于已证明物理隔离可靠，通路恢复不等于压力、流量、水质达标。
4. **方案完成、单个服务首次恢复、目标集合全部恢复分别计算。** 现有 `restoration_hours` 保留旧含义，不能直接冒充三者之一。
5. 比较候选方案时使用同一快照、故障、隔离、时间窗和指标定义；先判约束，再算整体效果，再以固定尺度和固定权重排序。不把多个单项措施的效用直接相加。
6. CUV 及人机意图按自主开发的设计思想落实：技能有契约、价值有配置、选择有条件、反馈有作用对象。**取得内部 CUV 内核不是本阶段前提**。

### 3.2 计算状态

下表是建议统一的业务计算状态，**不是要求本轮改动平台或 Agent 状态枚举**。现有异常如何映射，需在后续接口实现中落实并回归。

| 状态 | 判定 | 示例与数值处理 |
| --- | --- | --- |
| `succeeded` | 所请求且有实现依据的输出可计算 | 已知快照下图通路计算成功；不等于业务验收 |
| `partial` | 可独立提供部分结果，其他结果缺条件 | 图节点影响已知，居民户数未知；未知总数为 null |
| `insufficient_data` | 算法存在，但缺该次计算必需的有效输入 | 未知阀门状态、缺费用、缺资源容量、缺恢复事件时间 |
| `unsupported` | 当前没有相应实现或经过确认的计算协议 | 正式评分、失效概率、RUL、水力解、自动隔离优化、MILP组合 |
| `invalid_input` | 类型、引用、单位或相互关系不合法 | 重复ID、负金额、悬空节点、上下界相等；当前多以Pydantic/InputIssues异常拒绝 |
| `infeasible` | 已知条件明确违反约束 | 已知费用超过预算；不以“缺信息”推断必然不可行 |
| `failed` | 运行异常，未得到可信结果 | 求解器异常等；不把失败填0或伪装成缺数 |

推荐新增的错误明细结构：`{code, field_path, entity_id, reason, required_input, evidence_refs}`。例如缺备用费用：`code=MISSING_COST`、`field_path=actions[syn-backup].cost_fen`、`required_input=非负整数金额，单位分`。这些字段目前未全部存在。

“在已完整观察的8小时内未恢复”是有效事实，不等于数据不足。时间字段返回 `value=null`，原因 `not_recovered_within_horizon`，并给观察窗下界；不将 null 改为8小时。

### 3.3 版本与共识边界

各结果保留数据模式、快照/评价时点、模型版本、证据及适用限制。拟新增 `contract_version=1.0`、`input_fingerprint`、`metric_definition_version` 与现有计算版本分开登记。

人机反馈在算法入口的落点为：

| 反馈种类 | 允许改变的输入 | 应重算的内容 |
| --- | --- | --- |
| 事实/实体修正 | 经确认后的监测值、对象映射、阀门状态，形成新快照 | 相应评分或拓扑及受其影响的全部方案 |
| 目标/约束修正 | 目标服务集合、预算、资源容量、强制措施 | 约束与方案比较；服务集合变化还要重算恢复时间 |
| 价值偏好建议 | 新的价值配置草案 | 经确认后以同一效果基准重新算效用；不自动覆盖安全约束 |
| 解释偏好 | 解释粒度、展示顺序 | 不改变 Rs/Hs、图结果和效用数值 |
| 接受/拒绝建议 | 审核记录及所对应的快照/配置版本 | 不等于关阀、抢修或派单已执行 |

意图识别与澄清由 Qoder 的调用层承担。本文件只要求它最终传入确定的对象、时点、目标与参数；歧义未消除时不得由大模型补造字段。当前新时间函数尚未实现时应明确 unsupported，而非让语言模型代算。

### 4.2 H02 — calculate_legacy_health

**用途与版本。** 计算或读取 0.1.1 简化健康分。`calculation_mode=controlled_recompute` 使用H01输入；`fixture_replay` 只读固定历史输出。该模式名是建议公共参数，现有代码分别用两个函数，不支持任意外部文件路径。

**输入。** H01已验证的静动态行、时钟和来源。复读样例无需新静动态输入，固定读取B10对应结果及哈希；不能把样例管段挂接到S01虚构网络。

**数学定义及原始依据。** B04/B05。按下表顺序生成整数分 `s_i`（越大越差），或 None。

| 顺序 | 指标 | 原始权重w | 冻结的0.1.1评分规则 |
| --- | --- | --- | --- |
| 1 | 材质 | 0.13 | strip后精确匹配：钢塑/球墨铸铁/PE/PPR/涂塑=2，钢=3，铸铁=4，其他=3，空值=None |
| 2 | 管龄 | 0.13 | 上海评价年份−投运年份；[0,20)=1，[20,30)=2，[30,40)=3，[40,50)=4，≥50=5；未来年份无法评价 |
| 3 | 管径 | 0.07 | 有效正数：<100mm=4，[100,300)=2，≥300=1 |
| 4 | 埋深 | 0.06 | 两端算术平均d；有效正数：<0.5m=4，[0.5,1)=2，≥1=1 |
| 5 | 压力等级 | 0.04 | 字符串先判断含“高”=4，再含“中”=3，其他=2；空值=None |
| 6 | 动态压力 | 0.13 | 均值[0.2,0.4]=1；[0.15,0.2)或(0.4,0.5]=2；[0.1,0.15)或(0.5,0.6]=3；其他=4。CV<0.1加0，[0.1,0.2)加1，其他加2，封顶5 |
| 7 | 余氯 | 0.13 | 均值[0.3,0.8]=1；[0.1,0.3)或(0.8,1.2]=2；[0.05,0.1)或>1.2为3；其他=4。样本<0.05的比例严格>0.1时加1，封顶5 |
| 8 | 浊度 | 0.08 | 均值<0.5=1，[0.5,1)=2，[1,3)=3，≥3=4；样本>1的比例严格>0.1时加1，封顶5 |
| 9 | 瞬时流量 | 0.08 | CV<0.2=1，[0.2,0.4)=2，[0.4,0.6)=3，其他=4。只评价波动，不评价是否满足需求 |
| 10 | 风险点 | 0.15 | 0=1，1—2=2，3—5=3，6—10=4，>10=5 |

动态函数先 `to_numeric(errors="coerce").dropna()`；对留下的样本作等权统计，不按时间间隔加权。样本标准差与CV为：

\[
\bar x=\frac1n\sum_{k=1}^n x_k,\quad
s_x=\sqrt{\frac{\sum_k(x_k-\bar x)^2}{n-1}},\quad
CV=\begin{cases}s_x/\bar x,&\bar x\ne0\\0,&\bar x=0.\end{cases}
\]

这组阈值是原程序计算规则，**本契约不把它们认定为饮用水合规标准或供水达标判据**。余氯、浊度仅覆盖当前两个简化指标，不能据此声称已具备完整水质判定或污染输运仿真。

令 `a_i=1` 表示该指标函数返回非None分值，`W=Σa_iw_i`。对契约内有效的1—5分：

\[
R_s=\frac{\sum_i a_iw_is_i}{W},\quad
H_s=\operatorname{clip}_{[0,100]}\{100[1-(R_s-1)/4]\},\quad
completeness=100\frac W{\sum_iw_i}.
\]

W=0时Rs/Hs为null、占比0、等级“数据不足”；不除零。等级按**未舍入Hs**：≥90健康，≥75基本健康，≥60关注，≥40较差，其余严重。输出Rs保留3位，Hs和占比保留2位；不得先舍入再判级。权重顺序与指标顺序不调整。

**输出字段、类型与示例。** 当前 `SnapshotPayload.assessments[]`：

| 字段 | 类型/单位 | 示例A输出 |
| --- | --- | --- |
| `pipe_id/as_of` | string/datetime | `syn-001` / `2026-10-29T08:00:00+08:00` |
| `model_family/model_version` | string | `legacy_demo` / `0.1.1` |
| `legacy_result.Rs` | number或null，无量纲 | `1.3` |
| `legacy_result.Hs` | number或null，分 | `92.5` |
| `legacy_result.completeness_percent` | number，% | `100.0` |
| `legacy_result.grade` | string | `健康` |
| `indicator_scores` | 指标名→number | 材质2、管龄2、管径1、埋深1、压力等级2，其余1 |
| `main_risk` | string | `材质+管龄`；旧字段按原始分取前两项 |
| `properties/monitoring` | object | 管径300；动态压力均值0.3、CV0等 |
| `data_issues/evidence_refs` | string[] | 空问题表；受控重算及管段引用 |

当前 `indicator_scores` 省略None项。H03解释时按十项标准键补齐“未评价”状态，不能用省略推断其风险为0。

**兼容边界。** 核心为了复现保留：NaN管径或埋深可能落入1分；主流程缺风险点数可能转0；单条动态记录使样本CV为NaN并进入对应分支；均值0时CV记0；`PE管`不等于`PE`。严格入口已经阻挡其中多类输入，但不能说原核心已修复。历史结果按原样读，新数据走H01；修正评分含义需单独版本及批准。

**源码映射。** `scoring.py::recompute`→`pipeline.evaluate`→`score_pipe`→`indicators`→`aggregate_scores`→`assessment_rows`。样例读取：`provided_sample`先核验固定输出文件SHA-256。

**测试与预期。** 示例A：Rs=1.3、Hs=92.5、占比100%、健康；原500条历史B10保持平均82.4535及零差异；聚合全1→Rs1/Hs100，全5→Rs5/Hs0。后两项是聚合层数学边界，不保证十项原始规则可同时达到。年度时钟、显示舍入与判级分别回归，禁止因新解释改变历史结果。

### 4.3 H03 — explain_legacy_health

**用途与版本。** 契约1.0；2026年10月31日已实现为独立派生解释接口。输入H02的同次指标分与固定权重版本；不从两位Hs反推各项分值。

**输入字段。** `pipe_id:string`、`model_version="0.1.1"`、`indicator_scores:dict[标准指标名,int|null]`、`legacy_result`、`evidence_refs:string[]`。指标1—5、权重无量纲，完整字典固定十项顺序；未知键/非法分值拒绝。只拿到Hs而无指标分时返回insufficient_data。

**数学定义。** 对W>0、有效指标：

\[
\alpha_i=\frac{a_iw_i}{W},\qquad
c_i^{risk}=\alpha_i s_i,\qquad
d_i^{health}=25\alpha_i(s_i-1).
\]

有 `Σα=1`、`Σc=Rs`、`Σd=100−Hs_raw`。`c`衡量风险分的加权组成，`d`衡量相对1分基线的健康扣分；两者不可混叫“扣分”。缺失项有效权重为0，原始分和健康扣分展示null/未评价，不暗示“零风险”；对账只汇总有效项。所有数值使用未舍入分与权重计算，显示舍入的残差单列，不强塞给最后一项。

移除原有效项k且W>w_k时：

\[
H_s^{(-k)}-H_s=\frac{25w_k(s_k-R_s)}{W-w_k}.
\]

因此去掉高于当前均分的指标可能使Hs上升，去掉低于均分的指标可能使Hs下降。`aggregate.py:13`“缺失不会拉低Hs”的文字不成立；本轮仅登记文案修订，不改变计算代码。

**输出字段。**

| 字段 | 类型、单位 | 示例：仅材质2、管龄3有效 |
| --- | --- | --- |
| `valid_weight_sum` | number，无量纲 | `0.26` |
| `effective_weight` | 每指标number，无量纲 | 材质0.5、管龄0.5 |
| `risk_contribution` | 每有效指标number，无量纲 | 材质1.0、管龄1.5；合计2.5 |
| `health_deduction_points` | 每指标number或null，分 | 材质12.5、管龄25；合计37.5 |
| `evaluation_status` | 每指标evaluated/not_evaluated | 其余8项not_evaluated |
| `missing_indicators` | string[] | 管径、埋深等8项 |
| `legacy_completeness_percent` | number，% | `26.0`，复制原完整度含义 |
| `deduction_rank` | 指标名数组 | 管龄、材质；同贡献按标准指标顺序 |
| `legacy_main_risk` | string | `管龄+材质`，保留原字段值 |
| `reconciliation` | object | `Rs_raw=2.5,Hs_raw=62.5,deduction_total=37.5` |

W=0：返回insufficient_data，完整缺项表可用；不生成归一权重或贡献总和。声称统计置信度/质量系数q时为unsupported；本程序没有该模型。

**解释示例。** 其余指标均1，压力等级4、风险点3：Rs=1.42、Hs=89.5；压力扣3分，风险点扣7.5分。原`main_risk=压力等级+点`，健康扣分排序却为风险点在先。保留旧字段，并用独立新字段解释差异；不得悄悄把旧字段改成贡献排名。

**源码与测试。** 依据B05聚合公式代数推导，无新科学参数。仅材质2/管龄3：Hs62.5；移除材质→Hs50，移除管龄→Hs75；示例A扣分3.25+3.25+1=7.5。贡献核对允许浮点误差1e−9；测试应比较未舍入结果，并验证新增解释不改变H02结果。派生函数及独立回归已在2026年10月31日实现；见src/adapters/explanations.py与tests/test_scoring_contracts.py。

### 5.2 N02 — simulate_given_isolation

**用途与版本。** 已有图引擎0.1.0，契约1.0待审。输入N01全部字段；可选内存变更 `restored_edge_ids:string[]`、`valve_overrides:dict[valve_id,open|closed]`，分别映射现有参数`restored/overrides`。公开契约只允许已知故障恢复及有效阀操作；现有内部参数不会独立完整校验所有变更，应由D01/适配门禁约束后调用。

**数学定义与实现依据。** B07使用`MultiDiGraph`。启用节点构成V，开启且端点启用的边形成E；双向边添加双向弧，边键保留edge_id，平行边分别保留。多源BFS求正常可达集合A₀，以及故障删除、给定关阀和显式修复/开阀后的A₁：

\[
A_k=Reach(G_k,S),\qquad \Delta N=A_0\setminus A_1.
\]

对服务j及其接入节点集合V_j，定义：

\[
b_j(A)=\begin{cases}\mathbf1[V_j\cap A\ne\varnothing],&any\\
\mathbf1[V_j\subseteq A],&all.\end{cases}\quad
J_{aff}=\{j:b_j(A_0)=1,\ b_j(A_1)=0\}.
\]

只把正常可达→故障后不可达列为新增影响；正常时已不可达的对象另列，不重复算成本次故障影响。每个服务ID只计一次，但不同服务ID仍可能覆盖同一批住户，**ID去重不能代替人口覆盖去重**。要声称全片区总数，须确认映射覆盖范围与计数集合不重叠。

### 6.2 D01 — check_plan_constraints

**用途与版本。** 已实现同名公共函数于`src/decision/contracts.py`，决策算法版本1.0.0，复用原约束语义并补三态输出。通用envelope保留拓扑algorithm_version；决策单列decision_algorithm_version。

**输入。** N01情景、一个`ActionPlan`、其完整`Action[]`、预算、资源容量和强制措施。金额分、时间小时、资源单位按公共字典；示例为S01组合方案、预算400000、班组1组、送水车1辆。

**数学/逻辑定义。** 对给定措施集合A，不求解新的选择变量：

\[
cost(A)=\sum_{a\in A}c_a\le B,\qquad
usage_r(A)=\sum_{a\in A}q_{ar}\le capacity_r.
\]

并检查：强制集合⊆A；每项措施适用于当前故障；`requires(a)⊆A`；`conflicts(a)∩A=∅`；相关阀门可操作；生效时间、效果来源及备用条件齐备。成本/资源是**整个方案按现行口径累计**，不是最大同时占用量，不允许用“先后执行”绕过当前累计检查。

建议每条约束返回三态`pass/fail/unknown`：已知越界→fail，缺条件→unknown。只要存在fail，方案infeasible并同时保留unknown；无fail但有unknown则insufficient_data；全pass则可继续计算。已知费用之和已超过预算，即使另一费用未知，仍可判定违反预算，因为合法费用非负。

**现行差异。** 代码将措施阀门`operable=None`与False都视为infeasible。建议区分未知为insufficient_data、False为infeasible；这是**待批准的状态修订**。隔离前置检查目前将两者都阻断，也应保留具体原因。`requires_ids`目前只检查同选，不能宣称已验证施工时序。某阀在同方案内既开又关，现行效果阶段返回infeasible；需要时序的方案暂不支持推断，后续引入事件模型再处理。

**输出。** 建议`{status, plan_id, checks[], known_total_cost_fen, resource_usage, missing_items, violation_items}`；`checks[]`含约束ID、pass/fail/unknown、左/右值及单位。所有费用已知时total_cost_fen可用，否则只返回已知小计，不当总价。示例S01组合：总费370000分，资源`repair_team=1,water_truck=1`，预算400000通过。

**测试。** 预算300000→组合infeasible，金额超出70000分；备用费用null且其他已知项未超预算→insufficient_data；资源容量未提供→unknown，不按0；资源需求{}与null分别为已知无需求/缺数据；缺强制项或依赖项→infeasible；同选互斥项→infeasible。现有`test_k05_budget_changes`和`test_missing_effect_and_resources`可复用。三态、阀门可操作性及结构化结果已纳入test_decision_contracts.py。

### 6.3 D02 — evaluate_plan_effects

**用途与版本。** 已实现于`src/decision/contracts.py`，1.0.0，复用原整体效果逻辑及N02。对通过约束的**整个方案**在共同故障基准上重算，不分别计算单项收益后相加。

**输入。** N01情景、D01通过的方案及措施、固定正常快照。请求的窗口H用小时，费用用分；当前`effective_after_hours≤H`才应用其效果，等于H纳入终点状态。窗口外措施仍计入整个方案费用和累计资源，这一现有口径应明示。

**基准定义。** 至少区分：

- 正常状态G₀：冻结快照未施加本次故障。
- 故障基准G_f：同一快照，施加同一故障和给定隔离，不实施候选措施。
- 方案状态G_p(H)：从同一个G_f应用本方案在H前生效的全部明确变更。

各方案都与同一G₀计算新增断连，并与同一G_f计算改善。**不能把方案一的结果继续作为方案二的起点。** 建议基准指纹包含：快照内容哈希、as_of、故障、隔离、H、服务映射及覆盖范围、目标集合、服务判据、引擎及指标定义版本。已由build_decision_baseline实现内容指纹及离线声明核对；详细字段与范围见第二批交付。

设`J_f`、`J_p`分别为故障及方案相对正常状态的受影响服务集合：

\[
restored\_services=J_f\setminus J_p,\quad
newly\_affected=J_p\setminus J_f,\quad
remaining\_disconnected=|J_p|.
\]

这里的计数是**服务记录条数**，不是户数或人口。S01一所医院、80户一组、120户一组各算一条，共3条；不得以该指标声称三者影响规模相同。

**备用供水现行条件。** 对启动偏移t_a≤H的措施，代码检查：

\[
Q_a\ge D_a,\qquad L_a\ge H-t_a.
\]

Q/D单位m³/h，L单位小时。满足时将其列出的服务ID加入备用覆盖，再与`J_f`中critical服务取交集并去重。该指标只表示**输入假设下从启动到窗口终点具备容量和持续时间条件**，不证明启动前不断供、不证明输送路径、水质、压力或接驳条件合格。

同一送水资源不能被多个措施重复宣称覆盖。当前仅按资源累计和服务ID去重，尚无跨备用措施的真实输送/分配求解；真实业务应明确每项措施总需求、资源独立性和服务接受条件。条件不满足是`backup_covered=false`，不自动把整方案判为不可行；若业务要求“必须全程保供”，需提供硬约束规则单独检查，当前不能靠高效用抵消。

**离线效果输入。** 当前`OfflineEffect`包含as_of、fault_edge_id、isolation_plan_id、horizon_hours、evidence_ref、remaining_disconnected_service_ids、restoration_hours、backup_covered_critical_service_ids。前三者/窗口须与请求一致；恢复时间不得超过窗口；服务ID合法去重；备用覆盖限原故障影响的关键服务。离线结果是接收值，不声称本地计算或验证。正式比较还缺快照内容指纹、专业模型/参数版本、指标口径和验证依据；仅同一个时间戳不够保证完全同基准。

**输出与示例。** 当前包含`impact`、`metrics`、`backup_conditions`、`backup_covered_critical_service_ids`、证据及状态。已新增`baseline_key/restored_service_ids/newly_affected_service_ids`，不改旧指标含义。

| S01方案，H=8h | 终点通路受影响记录数 | 备用覆盖关键服务数 | 总费用/分 | 当前legacy restoration_hours |
| --- | --- | --- | --- | --- |
| 抢修 | 0 | 0 | 250000 | 6 |
| 备用供水 | 3 | 1 | 120000 | null |
| 抢修+备用 | 0 | 1 | 370000 | 6 |

备用不把图断连数3改为2；医院备用覆盖和网络通路是两个独立指标。组合方案的备用覆盖1仍有价值，是当前配置的既定选择；它不是经服务时长积分得到的额外效益。如业务要比较“减少多少失供小时”，应另建有时间线依据的指标，不能从此表推造。

## 7. T01 — compute_recovery_times：三个时间必须分开

**用途与版本。** 契约1.0；2026年10月31日已实现纯函数，算法版本1.0.0。按以下定义统计传入的服务状态时间线，不声称定义来自上游文件，不自动从措施推导服务事件。水力达标判据仍unsupported，不修改原评分。

### 7.1 现有restoration_hours究竟是什么

本地图计算路径中，代码收集分析窗内所有改变网络的措施生效时刻；若终点相对正常图的受影响服务集合为空，取这些时刻的最大值，否则null：

\[
t_{legacy}=\begin{cases}
\max\{t_a:a在窗口内改变网络\},&集合非空且J_p(H)=\varnothing\\
null,&其他.
\end{cases}
\]

这是**终点状态满足条件时，已应用网络措施中的最晚生效偏移**。它没有逐时求每个服务的恢复过程，也不包含所有非网络任务的结束时间。离线路径则直接接受提供方的restoration_hours，经部分情景条件校验；不能将两种来源自然认定为同一恢复定义。

因此保留旧字段值，并标识`restoration_hours_semantics=legacy_last_network_effect`（本地计算）或`provider_declared_unverified`（未获明确口径的离线输入）。D02已输出这些语义标签；离线时间需要明确兼容声明才可参与旧时间指标排序，声明不等于本地验证。

| `target_service_ids` | string[]，唯一 | 医院001、居民区C、居民区U | 本次要求恢复的确切集合 |

| `initial_availability` | service_id→bool或null | 三个对象在t=0均false | 故障/隔离后的初始状态 |
| `availability_events[]` | `{at_hours:number,changes:dict[id,bool]}` | t=6三对象均true | 已推导或观测的服务状态变化；同刻变更原子应用 |
| `timeline_complete_until_hours` | number，小时 | `8` | 已确认事件覆盖至何时；无事件不等于信息齐全 |
| `event_evidence_refs` | string[] | 仿真运行/工单/明确合成假设 | 事件来源及状态判据的依据 |

建议原始事件输入可进一步使用“修复边、开关阀、备用启停”生成服务可用时间线，再传入本函数。必须包含失效、备用到期或停止等导致服务再次不可用的事件，不能只记录好转事件。下游只接受经来源与服务判据检查的时间线，不能让LLM随意填true。

**三种判据要区分：**

- `topological_reachability`：仅图通路。可在N02基础上扩展逐事件图回放。
- `declared_service_availability`：依据外部明确的服务恢复记录或专业计算；注明接收而非本地水力验证。不能仅凭容量5>需求4就写医院已恢复合格供水。
- `hydraulic_compliance`：必须有压力/流量/水质判据、计算或测量结果及版本。当前无该引擎，返回unsupported；有服务目标值但无水力模型仍不能计算。

### 7.3 数学定义与输出

令行动a的开始偏移s_a、持续d_a、结束f_a=s_a+d_a。令A_j(t)为在明确判据下服务j于时刻t是否可用；事件间状态保持，事件时刻采用变更后的右连续状态。

| 指标/输出字段 | 定义 | 实际可计算条件 |
| --- | --- | --- |
| `plan_completion_hours` | `max_a f_a`，对方案全部行动取最大 | 每项行动明确结束时刻，或合法起点+持续时长；含非网络任务。缺一项则该指标insufficient_data |
| `service_first_restored_hours[j]` | t=0不可用对象的`inf{t∈[0,H]:A_j(t)=1}` | 每服务初始状态、完整事件及判据。t=0已可用时返回0并标already_available，不称“故障后修复” |
| `first_target_service_restored_hours` | 在t=0不可用的目标中，最早出现的恢复时刻 | 可选集合摘要；已在t=0可用的对象不参加此最小值；没有初始失供目标则not_applicable |
| `all_target_services_restored_hours` | `inf{t∈[0,H]:∀j∈J_target,A_j(t)=1}` | 所有目标在同一时刻满足判据；完整时间线和共同目标集合 |

**全部恢复不总等于各自首次恢复时间的最大值。** 例如A在2h恢复、3h再次中断、6h再恢复，B在4h恢复并保持：首次分别2/4h，最大为4h，但二者首次同时可用是6h。只有各服务恢复后不再中断等单调条件成立时，才能用max首次时间简化。

该“全部恢复”定义是首次同时恢复；若业务要求“此后持续恢复至H”或持续30分钟达标，应另定义稳定恢复指标并提供持续规则，不能在本轮含糊合并。

若目标集合非空且t=0已全部可用，全部恢复字段给0并标`already_available`，说明没有等待恢复过程。确认一个首次时刻，只需从0到该时刻的状态连续完整；证明“截至H仍未恢复”则必须覆盖至H。不能因后半段数据缺失而抹去前半段已确证的首次恢复，也不能以一个晚到的可用观测猜测其首次恢复时刻。

每个时间输出建议使用：`{value_hours:number|null,status,criterion_id,time_basis,reason,observation_horizon_hours}`。可选下界 `lower_bound_hours`及`lower_bound_exclusive`：完整观察[0,H]仍未恢复时，恢复时间（若最终存在）严格大于H，不将H当实际值。总体部分时间可得时为partial，各字段保留自己的状态。

### 7.4 边界条件

- 事件同刻原子应用；同一个状态被同刻赋true/false则invalid_input，不靠列表最后一项覆盖。
- H时刻恢复计入；H之后的已知计划事件可备注，但不填成窗口内恢复值。
- 计划全部行动的结束时刻若已知在H之后，`plan_completion_hours`仍可给其确切计划值，并标`beyond_horizon=true`；不同于恢复指标的窗口观察。
- 空目标集合为not_applicable，时间null；不能据“对空集全称为真”报0小时完成保供。重复目标ID拒绝。
- 完整时间线内一直未恢复→`not_recovered_within_horizon`；时间线不完整→insufficient_data。状态未知前的精确首次恢复时间不可猜；可另给已观察到恢复的上界，但不能冒称首次。
- 当前S01只有生效偏移，没有所有任务的明确完成时间。其现有`restoration_hours=6`可复核；**方案全部完成时间不可据此确定**。

## 8. G01 — check_calculation_capability

**用途与版本。** 已实现于`src/capabilities.py`，1.0.0，将“当前没有算法”和“已有算法缺本次数据”区分。作为确定性能力合同供Qoder调用，不负责实现LangGraph路由。

**输入。** `capability_id:string`、`requested_outputs:string[]`、`requested_semantics:string`、`input_manifest:object`。manifest须包含注册表要求的实际内存输入（snapshot、request、metrics等），不接受ready=true代替数据，不包含凭据或任意文件路径。精确字段与语义可由list_calculation_capabilities读取。例如capability=`failure_probability`，requested_outputs=`["failure_probability_1y"]`；或capability=`given_isolation_topology`、semantics=`topological_reachability`，manifest提供snapshot和request。
