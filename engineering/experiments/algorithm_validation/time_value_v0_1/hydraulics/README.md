# 合成水力基准 v0.1

2026-11-01 实际运行。数据标记：`synthetic_fixture`；算法标记：`candidate`。这是独立候选实验，未接入工程 API、智能体、比赛网站或任何正式生产模型。

## 可重复运行

在 `D:\重通院管网项目` 使用已有环境，不需要安装新依赖：

```powershell
.\.venv-cuv\Scripts\python.exe -X utf8 -B -m src.algorithm_validation.hydraulic_baseline
.\.venv-cuv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests/algorithms -p test_hydraulic_baseline.py -v
```

本轮版本：Python 3.12.14、WNTR 1.4.0、NetworkX 3.7、原生 EPANET 2.2.0（`EN_getversion=20200`）。**4 个稳态求解完成、7 项长期回归通过**。`results.json` 记录来源与源码 SHA-256、数值、单位、求解警告和质量平衡。`normal_pda.inp` 是唯一基础输入，其余 3 个 INP 是对应状态的派生输出，均可独立用 EPANET 读取。

跨服务器迁移只需本脚本、对应测试及本目录下的 `normal_pda.inp`，保持项目相对目录；**运行时不依赖其他派生 INP、旧 `src/cuv_reference`、旧 CSV 或旧结果 JSON**。在独立水力实验虚拟环境安装 `wntr==1.4.0` 和 `networkx==3.7` 即可，不能默认工程 `.venv-agent` 已安装 WNTR；不需要改动共享生产环境。Linux 对应命令为该独立环境的 `python -m src.algorithm_validation.hydraulic_baseline`。来源 CSV 和旧构造代码的哈希作为导出时 provenance 保留，并与本次实际读取基础 INP 的哈希分别记录。运行时不覆盖基础 INP，避免输入/输出形成哈希循环。

普通 `EpanetSimulator.run_sim()` 在本机遇到原生水力临时文件 Error 305。本基准使用 EPANET 的逐步水力 API：`ENopenH → ENinitH(0) → ENrunH → ENcloseH`，关闭水力历史文件保存，实际求解 `t=0`；不是解析 INP 或用图算法冒充水力计算。所有 native handle 在 `finally` 中关闭，临时文件自动清理。没有运行水质求解。

## 复用的网络与限定

基础 INP 由既有 `src/cuv_reference/run_example.py:build_network` 和 `04_实施方案/对接样例_v0.2/{nodes,pipes}.csv` 导出；运行时直接读取该 INP，再按下表状态改 P1/P4 开关及 DD/PDD 模式，保留原物理参数，没有改写原样例或复制整套旧包。

| 对象 | 合成参数 |
|---|---|
| 水源 S / B | 固定水头 60 / 42 m |
| 节点 J / H / R | 标高 10 / 15 / 12 m；需求 0 / 7.2 / 10.8 m³/h |
| P1：S—J | 长度 1000 m，直径 200 mm |
| P2：J—H | 长度 500 m，直径 100 mm |
| P3：J—R | 长度 500 m，直径 150 mm |
| P4：B—H | 长度 2000 m，直径 50 mm，正常关闭 |
| 全部管段 | Hazen–Williams 粗糙系数 120，无泵、储水设施、止回阀或自动控制 |

正常状态 P1 开、P4 关；中断状态二者均关；备用状态 P1 关、P4 开。图可达使用所有节点及开启的普通管段构成无向图，在这个特定网络中成立；不能直接推广到含止回阀、泵控或储水的网络。

PDA 最低压力水头 0 m、充分供水压力水头 20 m、指数 0.5 均是**合成测试参数，不是医院设计或法定标准**。H 是测试服务节点，不代表实际医院。压力单位为水头米，不是 MPa；INP 与原生工具返回流量单位为 L/s，脚本除以 1000 转为 m³/s，再乘 3600 展示 m³/h。

## 核验公式与误差

PDA 将节点供水视为需求与压力的函数，实际检查采用：

\[
q_i(p)=\begin{cases}0,&p\le0\\d_i(p/20)^{0.5},&0<p<20\\d_i,&p\ge20\end{cases}
\]

节点质量平衡残差为“进入流量 − 离开流量 − 节点外用水”；全网残差为“水源净出流 − 节点外用水之和”。正常、备用、断网、DDA 的全网残差分别约为 `1.60e-8`、`-4.19e-8`、`-7.25e-8`、`-3.51e-7 m³/s`，均小于本基准绝对容差 `1e-6 m³/s`。容差是求解回归的数值界限，不是允许的业务供水偏差。对已连通 PDA 节点，还用上述分段公式独立核对需求结果。

EPANET 水力精度参数明确取 `1e-5`，最大迭代 200，附加 head error `1e-7 m`、flow change `1e-9 m³/s`。充分供水判断的数值容差为供水比 `1e-4`、压力 `1e-5 m`。原始数值全部保留；仅“可用于需求的水量”限定在 `[0,需求]`，避免正常工况极小超量被当作额外收益。

依据：[EPANET 2.2 分析算法](https://usepa.github.io/EPANET2.2/12_analysis_algorithms.html)的质量守恒与压力驱动需水关系，以及[WNTR 水力仿真说明](https://usepa.github.io/WNTR/hydraulics.html)。关闭管路与需求边界的高阻数值处理也说明了为何须保留断网 raw 值而单独判定服务。

## 对时间价值计算的使用边界

该基准实证了“有水源通路”只能支持拓扑判断。将备用状态持续时长乘以 100% 服务恢复，会高估这份 fixture 中 H 的供水收益；应先获得每个时间片的压力、需求和可用供水，再积分缺水量或不满足时长。

本轮是四个独立稳态，不是动态水力或水质时间线。后续每个动作事件间的稳态复算需明确固定需求假设；如有水箱、泵切换、时变需水或水质传播，必须配置延时仿真与相应边界。正式阈值、需求曲线、管径/粗糙度/高程校核、现场压力流量标定和质量证据尚待提供。本输出不证明真实项目方案可用，也不能据此确定业务效用权重。
