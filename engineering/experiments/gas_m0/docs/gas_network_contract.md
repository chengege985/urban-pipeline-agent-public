# 燃气54节点合成网络与首例合同

版本：`gas-network-candidate-0.1.0` / `gas-graph-candidate-0.1.0`。性质：GAS-M0候选、synthetic、not_business_validated。未接入FastAPI、Agent或React，不构成现场操作方案。

## 一 提取依据与可重复性

原件为工作区根目录`燃气动态风险推演_前端示例原型_v1.html`，SHA-256：

`21671fbdd368a4fb6e8757f18af91e5aa69a0221098b022c00009a4bf4a88832`。

提取器只执行从`function mulberry32`至`链C PIR`之前的已审阅代码段，保留原固定种子20261104、原数组构造、边端点、非阀节点并查集及`unitValves/disconnected`。该段SHA为：

`e354dba828fc226d64ee7b848b162cd3712a783952f447aec075b81b013baaf5`。

先核对完整原件和代码段哈希，再在Node vm中执行。vm不暴露require、process、fetch、定时器、文件系统、DOM或宿主回调，禁止动态代码生成且设执行超时；不执行页面、扩散、概率、风险、热点或动画计算。**vm不是任意不可信代码的安全沙箱，本次允许执行的依据是固定哈希与人工审阅。**

本次实际环境为Node **v24.14.1**，V8 **13.6.233.17-node.44**。原型使用`.sort(()=>rnd()-0.5)`，比较器不满足全序，排序调用次数会影响后续随机序列。仅固定种子不足以保证跨引擎相同，提取器因此拒绝其他运行时；已交付JSON是可跨环境读取的规范fixture，不要求服务器Node22重新生成它。

源码原始边明确由`a/b`节点引用建立，不使用SVG线条、坐标距离或空间交点猜测连接。示意坐标仅用于显示。原型把像素按0.5 px/m换算的长度、人口与空间估计均进入demo_parameters，不能作为GIS或实测长度。

重提取命令，输出目录必须没有既有交付文件：

```text
node tools/extract_gas_network.mjs --source <原始HTML路径> --output-root <新的隔离输出目录>
```

默认原件位置相对专项目录解析；可显式指定原件。原件哈希改变时，在执行和创建输出之前拒绝。输出已有时拒绝覆盖，须重提取到新目录后比对。原始HTML始终不修改。

## 二 实际结构

| 实体 | 数量 | 来源与语义 |
|---|---:|---|
| Node | 54 | 原9列×6行；19 junction、2 regulator、31 valve、2 source |
| Edge | 73 | 直接保留原`edges[].a/b`；边ID与管段ID分开 |
| Pipe | 73 | 原`K-001`等对应一个Pipe；与Edge显式一对一 |
| Valve | 31 | 原`node.type=valve`；独立Valve ID引用Node，采用node_cut |
| Source | 2 | 原A门站N20、B调压站N38；无真实压力或容量 |
| Consumer | 46 | 21组户数+21组商户数+4处设施；不是46个真实用户记录 |
| Service | 46 | 每个Consumer对应一条服务；原始接入节点由源码引用确定 |
| IsolationUnit | 35 | 原“非阀节点将相邻边归于同单元”的并查集结果；不是自动最优方案 |
| 原型上下文 | 4 | 常态、冬季保供、重大活动、地灾汛期；保留为context，不冒充事件记录 |
| 新增首例 | 1 | K-001给定故障及其原型单元隔离；新建3个合成事件 |

聚合户数合计5085，商户数406，均为原型固定种子生成值。Consumer的count单位分别为household、business、facility，设施的1表示一处设施，不是人口。当前候选要求这些聚合计数已知且为正整数；**None计数直接拒绝**，尚未实现“已知小计+未知对象数”合同。

所有ID采用`syn-gas-*`前缀，并按node、edge、pipe、valve、source、consumer、service分别命名。`prototype_id`或`prototype_node_id`保留原标识。示例：

```text
syn-gas-edge-K-001 → syn-gas-pipe-K-001
syn-gas-edge-K-001: syn-gas-node-N00 ↔ syn-gas-node-N01
syn-gas-valve-N11 → syn-gas-node-N11
syn-gas-service-household-N00 → syn-gas-consumer-household-N00 → syn-gas-node-N00
```

`from_node_id/to_node_id`只是原数组的存储顺序，`direction=undirected_connectivity_only`。没有证据说明真实上游/下游、压差、流向；调压节点在当前图内仅作通路节点，不模拟调压、止回或气体物理过程。

### 阀门语义不能直接套现有平台

原型Valve是“节点切断”：关闭该节点后所有关联边都不能穿越。`incident_edge_ids`由明确端点求得，是关联列表，不是“一个阀门对应一条管段”的控制映射。

当前供水平台的`IsolationPlan.valve_ids`指向标记为阀门的边，与本例node_cut并不等价。本阶段不直接导入现有Snapshot Schema，不把节点阀改名为某条边或把邻接管段伪装成阀门。后续须新增受测行业Adapter或批准明确合同后接入。

### 原型中必须显式保留的边界

原型将医院FAC-01明确挂到N24、养老FAC-04明确挂到N45，但两个节点均被随机过程标为valve。原`disconnected()`将所有valve/source节点排除，导致这些设施不进入原usersOf停气统计。

提取结果保留原始明确关联，不根据设施画面位置换接节点。候选对全部服务判断通路，闭阀节点上的设施会显示图不可达；这是有记录的服务统计修正，与原型过滤行为不同。户数与商户数在全部73个故障单元对照中仍一致。真实设施接入关系必须由业务数据核实。

## 三 首个故障与给定隔离案例

文件：`data/gas54_case.json`。网络ID为`syn-gas-network-html54-0.1.0`，案例ID为`syn-gas-case-K-001`。

- 给定故障边：`syn-gas-edge-K-001`。这是人为输入“边不可用”，不是模型预测发生泄漏。
- 给定隔离：原型单元16，阀N11、N13；明确停用K-001、K-002、K-003、K-004、K-005、K-015、K-017这7条边。原件`unitValves`与`units`提供关系，非自动现场方案。
- 新增合成事件：0h给定故障、0.5h给定隔离、1h观察状态。三个时点是本轮案例假设，原型没有这些事件记录；未借用原型固定5h停气时间。
- 分析窗口8h；任务结束时间null；没有维修、检漏、置换、放行或复气事件。

| 时点 | 图上变化 | 潜在中断聚合值 |
|---|---|---|
| 正常基准 | 全部54节点有来源通路 | 无基准失联服务 |
| 0h K-001故障 | N00与N10失联；N10仅通过K-002到N00，N00靠K-001连接其余网络 | 499户、41商户；4个聚合Service |
| 0.5h给定隔离 | 消费节点N00、N01、N02、N10、N12失联；阀节点N11/N13本身亦不可达 | 相对正常基准共1330户、103商户；10个聚合Service；无新增设施失联 |
| 1h观察 | 与0.5h完全相同，没有恢复事件 | 不因此推断任务已完成或供气恢复 |

1330户的独立加法为182+228+215+317+388；103商户为34+28+21+7+13。隔离相较故障阶段额外增加831户、62商户，但结果的`newly_*`统一相对正常基准，不能混作逐事件增量。

`data/gas54_result.json`保存纯函数实际结果，并绑定规范化输入内容SHA、算法版本、网络/案例/情景/方案ID和原HTML SHA。输出为partial：图事件可用，任务完成时间insufficient_data，实际燃气恢复、压力、流量、概率unsupported。服务`physical_supply_status=unknown`，图可达也不能显示为压力达标、可靠供气或可安全复气。

任务结束若显式给9h而分析窗口8h，保留`value=9`并返回`in_analysis_window=false`，不写成窗口内完成。缺少结束时点不使用最后动作时间顶替。任务结束不得早于最后一次given_isolation；0h结束与0.5h隔离冲突会拒绝，0.5h结束可合法保留，之后1h纯观察不改变完工时间。

## 四 演示参数与未实现能力

`demo_parameters`保存各管段的原P/C/E、年龄、设计寿命、压力、示意长度、施工暴露、干预期，并列明：

- 阀门失败率0.15/0.10，5h/8h停气、3万/8万维修费用及效用换算系数。
- PIR、最小半径、6m衰减尺度、1.2m深差、0.08点火比例、空间体积对应半径。
- 原风险矩阵、等级阈值、主观权重、0.6/0.4混合、KAPPA、四次幂聚合、P95归一化。
- 12期Markov预设转移、干预比例、失效强度假设和原`p12`表达式；没有标定依据。
- Gi*的125px网格、375px邻域、0.05 FDR、1.96/2.58阈值，以及合成人口/土体/地下空间参数。
- 原始技能声明和数据可用开关；开关为true不代表实际已接收业务数据或模型。

这些参数仅为来源保留，候选图函数不执行它们。改变P、概率或5h停气参数不会改变图可达结果。未实现真实气力、泄漏率、积聚浓度、扩散、爆炸、人员伤亡、现场阀门指令和安全复气。

## 五 验证与下一阶段边界

`validate_network`校验类型、唯一ID、实体ID空间分离、端点、Pipe/Edge双向映射、Valve与全部关联边、多源、服务any/all、Consumer/Service接入一致、单位、计数和隔离单元引用。孤立节点显式列为warning并判为基准无通路，不补连边。结构有效不等于物理数据有效。

`evaluate_case`严格绑定网络、情景和方案；事件为完整状态切片，要求时点递增、在窗口内且符合给定故障/隔离。反例包含空接入、非法ID、错配Pipe/Valve、重复、bool、NaN/Inf、负数、文本小时、跨情景隔离、原有失联与双接入any/all。源SHA只检验完整格式并写入证据；来源真实性仍由提取器固定原件哈希及交付清单比对保证，不声称仅字符串验证完成认证。

本模块测试包括34项图/合同用例（其中1项内含73个原JS故障单元对照）及3项提取器用例。原JS对照是独立实现对照，不等于业务金标准；另外保留上述可手算首例。首次新增测试有2项错误预期，把K-001错误假设成存在替代通路；按原始边记录修正为N00/N10叶支断供，算法未为错误预期作调整，初次日志单列。

下一阶段可在GAS-M0验收后构建专用Snapshot Adapter和FastAPI集成测试。前置条件是明确节点阀语义、未知计数/部分记录合同、报告结果类型和来源认证；不得在当前受审Report验证器或冻结Agent内核中绕过身份规则。现阶段仅执行隔离纯函数和合成数据验证。
