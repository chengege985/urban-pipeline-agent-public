## 2. 首个合成例实际需要什么

完整输入定义见[最小输入与专业门禁](../data/gas_minimum_inputs.json)。这些是我方开发任务，暂不作为对外数据索取单。

| 输入 | 来自哪里 | 作用与不能推断的内容 |
|---|---|---|
| 节点ID、示意坐标 | HTML的`nodes[].id/x/y` | 构造对象和显示示意图；坐标不是GIS测量值 |
| 管段/边ID、两个端点 | HTML的`edges[].id/a/b` | 建图和选定故障；必须取明确端点，不能按图上距离连边 |
| 无向通路语义 | HTML原邻接构建 | 保留原型的双向连通假设；不推定实际供气上下游或气流方向 |
| 阀门及作用节点 | HTML阀门节点与隔离单元逻辑 | 保存原型“节点阻断”语义；不得凭空间位置改造成某根管段的边阀 |
| 气源及节点 | HTML明确标记的source | 多源通路起点；真实站场是否具有供气功能另确认 |
| 用户/设施及接入节点 | HTML明确挂在节点上的`hh/com/fac` | 计算潜在停气对象；真实人口或邻近建筑不能直接当接入用户 |
| 故障和给定隔离方案 | 固定原型选中边及对应候选隔离结果 | 可重放合成案例；不下发关阀动作，不推荐现场操作 |
| 事件和时间线 | 我方新建且明确标记synthetic的事件 | 事件排序和部分结果展示；不是原型中的历史监测记录 |
| network_id、case_id、内容SHA、状态 | 我方构建产物 | 追溯本地合成网络和案例，不需要业务人员填写 |
| dataset_id、snapshot_id、run_id | M1接入后由可信平台签发，本轮没有这些身份 | 不能由HTML、客户端或本地候选代签；不能把合成network_id直接冒作平台快照 |

实际候选键名为`nodes[].node_id`及`layout`、`pipes[].pipe_id`、`valves[].cut_semantics/incident_edge_ids`、`scenario.fault_edge_ids`、`events[].kind/time_hours`及完整状态ID集合；不是说明性概念名`Node.id`、`action_scope`或单个`target_id`。字段存在和SHA格式通过只证明结构，不认证来源；真实接入仍由平台分类和授权。

目录没有补齐以下关键关系：**Node稳定ID、管段端点ID、阀门作用节点/边、站场—节点关系、服务对象接入及any/all规则、故障发生与关阀等可靠事件时点。** 目录有X1/Y1/X2/Y2，不等于已经给出了端点ID；有站场名称，不等于该站场是当前启用气源。

## 4. 专业模型启动条件

| 功能 | 当前目录线索 | 仍需什么才能启动 |
|---|---|---|
| 管网压力/流量 | 设计压力MPa、管径mm、介质、站场压力范围与设计气量 | 气体组分、温度、标况、管道内径/粗糙度/高程、气源与用户边界、调压止回机理、同步实测和校准案例；由专业模型团队与运营调度确认 |
| 泄漏扩散与地下积聚 | 设备台账、风险点、空间位置 | 泄漏口与释放工况、气体性质、土壤及通道、地下空间与通风、浓度序列及验证案例；设备存在不等于已有读数 |
| 事故后果 | 风险点描述、预案关联码 | 已确认后果模型、暴露数据、场景与适用范围、不确定性和验证依据；HTML中的PIR/点火概率不能直接作为业务结论 |
| 安全复气 | 抢险结束、整改完成等线索 | 检漏、置换、验收、放行及用户复气等实际判据和记录；“作业完成”不自动等于“服务恢复” |

专业模型未通过单独门禁前，只做图通路和给定事件。不得沿用供水的PDA、水头、余氯、送水量或其单位来计算燃气。

## 5. 已发现的字段陷阱

1. 第205行“材质”被目录标为主键；不能据此作为唯一管段ID。第174、197、217行等以名称作主键，也需核验跨表稳定性。
2. 第206行“压力”、208行“管径”、210行“长度”未明确单位。第104/186行设计压力明确MPa，第105/187行公称直径明确mm，不能将后两者的单位默认移植给其他资源。
3. 第200行设计输配气量单位原文是“天/万方”。保留原文并标待确认，不自行改为万m³/天或标况气量。
4. 第77、85行字段名称为“整改完成时间”，描述却是“数据记录时间”。目前只能保存原值，不能用于可靠完工时点。
5. 第96、320行“抢险结束时间”不代表安全复气；接警、出警、到场、关阀和复气是不同事件。
6. 第251—290行“燃气泄露风险点”实际为设备台账；缺浓度、单位、采样时点。第295/296行风险当前值/阈值也未给出明确指标、单位、采样窗，不能直接赋给G05/G06。
7. 第420—440行巡检完成率资源已注销，且内容为区域指标。它不能替代单管段巡检工单，也不能用来声称G14已经具备。
8. 手机、姓名、身份证、责任人电话、设备IP等本阶段不需要。只保留字段定义和权限元信息，不索取其业务值。
9. 第201/202行仅为进站/出站压力范围（MPa），原文未说明是设计范围、运行边界还是实测范围。候选目标保留为`inlet_pressure_range_raw_mpa`与`outlet_pressure_range_raw_mpa`，由业务方确认性质后才能适配；第199行明确的设计压力仍保留设计含义。

G01—G15的目录候选关联已在`gas_catalog_438.json.indicator_source_candidates`逐项列出，包括“直接候选属性”“只有设备/汇总线索”和“目录缺项”。没有把城市体征的`idxcode`自动映射成燃气G01—G15。

## 6. 重建与验证

构建器只读固定SHA的原Excel，不访问网络、接口或数据库。变更了原Excel后会拒绝继续套用旧行号映射，必须重新审阅。输出必须是尚不存在的新目录；既有空目录、非空目录、文件或符号链接都会被拒绝，文件独占创建，不覆盖交付`data/`。JSON显式保留CRLF，CSV保留UTF-8 BOM及原单元格换行，Linux/Windows均按同一字节合同重建。

在179已确认的隔离燃气仓库根运行；`../../`仅指该隔离工作区的只读来源副本：

```bash
verify_root=$(mktemp -d /tmp/gas-matrix-verify.XXXXXX)
/workdata/WaterPipNet/.venv-agent/bin/python -B tools/build_gas_field_matrix.py --source "../../数据目录及数据项20261015160600.xlsx" --out "$verify_root/rebuilt"
/workdata/WaterPipNet/.venv-agent/bin/python -B -m unittest discover -s tests -p "test_field_matrix*.py" -v
```

重建结果先与交付文件比较；本命令不向`data/`复制。修复候选在179新目录重建、逐字段复核后，由交付流程显式接收必要变更。
