**定位**：这是提供方的 10 项指标简化评分，不是正式方案的 P/C/R/H 体系；没有失效概率、

和适配层的起点。本包不属于新算法研发。

### 0.1.1 修复与验证

- 比对双方均检查管线编号唯一性，任一方重复则不通过；返回 `unique_keys`、`actual_unique_keys`、`reference_unique_keys`。
- `evaluate()` 与 `run()` 共用上海时区归一化。同一跨年时刻的 UTC、上海及对应无时区当地时间表示，评分一致。
- 先保存最小元信息，输入哈希和依赖查询异常纳入失败处理；错误时保留运行 ID、`failed` 状态、`error.log`、元信息及最近运行入口。无法写运行记录目录或日志时，文件系统异常仍向上传递。
- “风险点ID列表”的空字符串与 Excel 空单元格视为等价，但字面 `"nan"` 不与缺失混淆。

边界验证采用内存 Excel 和文件写入 Mock，不新增一次性测试脚本或失败运行目录。0.1.1 已完整运行500条样例，另外只读核对新导出的 Excel 三张表及 TXT 五项统计，均与参考一致。内置 `compare` 的范围仍仅为内存主表，不能以其通过替代完整导出验证。

## 三 计算逻辑一页版

```text
静态表（每管段 1 行）──► 材质 / 管龄 / 管径 / 埋深 / 压力等级 ──► 5 个 1—5 分
动态表（每管段 N 行）──► 动态压力 / 余氯 / 浊度 / 瞬时流量 ──► 先聚合（均值、CV、超标率）再打 4 个分
动态表第 1 行的"风险点数量" ──► 0/1-2/3-5/6-10/>10 ──► 1 个分

Rs = Σ(w × 分) / Σ(w)           只对有分值的指标求和，缺项剔除后重新归一化
Hs = 100 × [1 − (Rs − 1) / 4]   裁剪到 [0, 100]
等级：≥90 健康 / ≥75 基本健康 / ≥60 关注 / ≥40 较差 / 其余 严重
可信度 = 有效权重 / 总权重 × 100  （是"有多少指标参与"，不是准确率）
主要风险因子 = 原始分最高的两项
```

权重：材质 .13、管龄 .13、管径 .07、埋深 .06、压力等级 .04、动态压力 .13、余氯 .13、浊度 .08、流量 .08、风险点 .15。

## 四 与原程序的刻意差异

只改"环境性"部分，不改任何会影响数值的规则：

| 原程序 | 本包 | 原因 |
| --- | --- | --- |
| 从用户桌面读写固定文件名 | 路径由参数传入；输出按运行 ID 落盘，不覆盖 | 服务器可运行、可追溯（台账 P05） |
| `datetime.now().year` 算管龄 | 显式 `as_of`，两个入口统一为上海时区后取年份 | 回放可复现（P04） |
| 失败 `sys.exit(1)` | `run()` 捕获输入与计算异常，返回失败元信息并写 `error.log` | 便于被调用；目录不可写等异常仍会抛出 |
| 无运行记录 | `experiments/pipe_health/<run_id>/metadata.json`：输入哈希、环境、汇总、比对 | 符合工作区落盘约定 |
| TXT 只有"生成时间" | 增加"评价时点"一行；权重段由 config 生成 | 避免两处维护同一组数字 |

## 五 保留的已知问题（勿在不知情时"顺手修掉"）

以下行为与原程序一致，修正后可能改变相关输入的结果；完整样例一致并不代表边界行为已正确。改之前先与评分责任方确认口径，改之后用 `compare` 记录差异。

| 台账 | 位置 | 现象 | 修正思路 |
| --- | --- | --- | --- |
| P01 | `indicators.diameter_score` | 管径 NaN 落到 else 得 1 分（最低风险），且不记"数据问题" | `float()` 后加 `isnan → None` |
| P02 | `indicators.depth_score` | 任一端埋深 NaN，均值 NaN，同样得 1 分 | 同上 |
| P03 | `pipeline.read_risk_point` | 风险点数量缺失/非法被置 0 → 1 分，可信度仍 100% | 保留 None，进"数据问题"并降可信度 |
| P06 | `aggregate.aggregate_scores` | 主要风险因子按原始分而非加权贡献排序；`"风险点风险".replace("风险","")` 变成"点" | 按 `w×分` 排序；显示名单独维护 |
| — | `pipeline.read_risk_point` | 只取第一条动态记录的风险点数量 | 约定评价窗口内的聚合方式 |
| — | `indicators`（动态 4 项） | 不按评价时点过滤序列；单条记录时 CV=NaN 落最差波动档 | 在 `evaluate` 前按时间窗切片 |
| — | `indicators.material_score` | 材质只精确匹配 7 个值，其余默认 3 | 补别名映射表 |

## 六 运行

```bash
cd /workdata/WaterPipNet/01_工程项目
../.venv-baseline/bin/python -B -m src.pipe_health                 # 默认：样例输入 + 基线时点 + 与参考结果比对
```

依赖与 `.venv-baseline` 相同：pandas 2.2.3、numpy 2.2.6、openpyxl 3.1.5，见 `configs/baseline_requirements.lock.txt`。

## 七 下一步怎么在这上面开发

1. **先确认口径再改规则**：P01—P03 的缺失值处理、H 定义等归上游评分责任方；本包只接收确认后的版本，改动后升 `PACKAGE_VERSION`，并保留 0.1.0 的运行记录作对照。
2. **加时间窗**：在 `evaluate` 中按 `as_of` 对动态表切片，再传给打分函数；这是接入真实多日监测的第一步。
3. **适配层**：把结果表映射到接口草案 I02 的字段（管段 ID、评价时点、分值、等级、缺失项、版本、运行 ID），不在打分函数里混入接口逻辑。
4. **测试**：规则一旦允许修改，先把当前 500 条结果固化为 `fixture`，再为 10 个打分函数补边界用例（NaN、0、负数、单条记录）。
5. 任何新能力（概率、拓扑、CUV）放新包，不要往这里叠。
